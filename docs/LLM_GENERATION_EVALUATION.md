Other currently documented Grok options remain comparison candidates where their context, price, latency, or reasoning behavior could better fit the deployment envelope. The newest or most capable model is not selected automatically.

## Controlled benchmark design

Use supplied evidence packages generated by the validated retrieval system. Do not give the model unrestricted corpus access. Each request must include evidence IDs, source filename, SHA-256, source status, report family, scope, date/period, table/row/column or PDF page, raw and normalized values, and uncertainty labels.

Representative cases:

| Case | Class | Main checks |
|---|---|---|
| Q002 | policy | grounded explanation and page/source citation |
| Q003 | exact lookup | exact report/format identity preservation |
| Q009 | structured numeric | numeric value, state/district, row/column citation |
| Q036 | cross-document | state alignment, common date/schema, complete coverage |
| Q014 | provenance/excluded source | audit-only citation and no corrupted-source data use |
| synthetic insufficient case | insufficient evidence | abstention and no unsupported completion |

## Required assertions

1. Answer only from supplied evidence.
2. Preserve numeric values, units, signs, and precision.
3. Respect state, district, report-family, date, and version filters.
4. Do not infer version precedence from filename suffixes.
5. Abstain or qualify when evidence is insufficient or conflicting.
6. Preserve source filename, SHA-256, page/table/row/column provenance.
7. Produce schema-valid JSON for a typed answer contract.
8. Measure unsupported factual claims and citation mismatches.
9. Record latency, input/output tokens, finish status, retries, and estimated cost.

## Suggested output schema

```json
{
  "answer": "string",
  "status": "ANSWERED | INSUFFICIENT_EVIDENCE | CONFLICTING_EVIDENCE",
  "claims": [
    {
      "text": "string",
      "evidence_ids": ["string"],
      "numeric_value": null,
      "citation_valid": false
    }
  ],
  "limitations": ["string"]
}
```

The application must validate citations and numeric claims after generation. Structured output guarantees shape, not truthfulness or evidence support.

## Cost and deployment notes

The current xAI model page documents token pricing, but production cost requires query volume and token distributions. Use:

`cost = input_tokens / 1,000,000 * input_price + output_tokens / 1,000,000 * output_price`

Secrets must be supplied through a secret manager or protected runtime environment. Do not place API keys in code, logs, benchmark artifacts, or prompts.
